# 0008. 输出覆盖，但内容相同则跳过；写盘原子、台账清理、EXDEV 不静默回退

- 状态：Accepted
- 日期：2026-10-27
- 来源：wayfinder 票「输出落盘与链接语义」（#6）

## 背景

任务持久、可整体重跑，幂等基准是输出目录（不是 DB）。重跑会重复写同一批产物；媒体服务器按 mtime 判断变化，无脑重写会让它重扫一切。硬链跨设备（EXDEV）在 NFS + 本地盘混布下真实存在。

## 决定

- `output.with` 键面：`root`（必填）/ `dir_template`（默认 `{{ number }}`）/ `file_template`（默认 `{{ number }}-cd{{ part }}`，只管分片）/ `link ∈ {hardlink, copy, move}`（默认 `hardlink`）/ `required_fields`。
- **覆盖，但 `sha256` 相同且文件仍在则跳过写入**（保住 mtime）。
- **清理**：按上次落盘台账删掉本次不再产出的旧产物；**只删台账里记过、且落在该任务输出目录内的文件**，台账之外一律不动。
- **原子写**：同目录 `.tmp` → `rename`；`hardlink` 直接产生最终名。
- **EXDEV → 任务 `failed`**，提示改 `copy|move`，**不自动回退**（静默回退会让媒体库悄悄翻倍占空间）。
- 图片固定走 move 语义（内存字节直接写最终路径，不设暂存目录），不受 `link` 开关影响。
- 落盘台账 `file_rows` 是幂等跳过与重跑清理的依据。

## 替代方案

- 无条件覆盖（旧仓部分如此）：被否 —— 每次重跑都刷新 mtime。
- 只看台账不看磁盘就判定「已写」：被否 —— 会把被外部删掉的文件误判成已写。
- EXDEV 静默降级 copy：被否 —— 属于部署形状问题，应被看见。

## 后果

- 幂等长在真文件系统上（验收必须用真临时目录 + 真挂载点造 EXDEV）。
- 图片扩展名按引擎魔数嗅探 + 白名单（`jpg/jpeg/png/gif/tbn` 原样，`webp`/`svg` 转 `.jpg`），README 的 `.png` 是笔误。
- `thumb` 永不写（14 字段里没有源供给它）。
