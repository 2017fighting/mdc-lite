# 0002. 分组先于解析，合并以「分片标记」为正面证据

- 状态：Accepted
- 日期：2026-10-27
- 来源：wayfinder 票「番号解析与文件分组规则」（#3）

## 背景

README 要求先按文件名相似度分组、再解析番号，理由是「一个正则很难同时切番号和 cd 分片」。但字面的「同目录 + Levenshtein ≤2」会把同目录的相邻番号（`ABP-123` / `ABP-124`）合成一组；而旧仓是先解析、后按 `番号 + 目录 + 版本键` 分组，靠版本键避免吞并。这是新旧两版最尖锐的一处冲突。

## 决定

- **先分组、后解析**；主干 = 剥掉噪声（sanitize / 广告域 / 技术 token / 分辨率 / 旗标 / 字幕标记）后的文件名。
- 合并必须有**正面证据**：两档标记表（确定标记无条件生效；条件标记需同目录兄弟文件同意，判据 = 剥掉它之后主干相同的文件 ≥2 个）；主干逐字相同即同组；主干距离 ≤ `max_distance`（默认 2）且**双方都带生效标记**才合并。
- 字母形态**排除 `C`**（中字版是重复版本，不是分片）。
- 剥离只在 `group` 一处发生，结果随 `Group` 产物传给 `parse`（每文件带 `{stem, marker{text, index, confident}}`）；`parse` 不配剥离表。
- 求值顺序是**全匹配 + 包含裁决**（不是 README 的 first-match-wins）；剩多个番号 → `ambiguous` → 待补号。

## 替代方案

- **(a) README 字面（距离 ≤2 即合）**：被否 —— 会吞相邻番号。
- **(b) 旧仓的顺序（先解析后按番号分组）**：被否 —— 纯数字尾标（`ABC-123-1`）单文件无法判定是分片还是番号。
- **(c) 标记表两处各配**：被否 —— 条件标记要看兄弟文件，只能一处判定。

## 后果

- `Group` 契约多一个标记字段，`Group.Parts` 按分片序号排（primary = 分片序号最小者，修掉字典序 `cd10 < cd2` 的坑）。
- `parse` 变成对「主干」的纯函数。
- 需要一批真机文件名做回归语料（教训：夹具必须来自真机捕获）。
