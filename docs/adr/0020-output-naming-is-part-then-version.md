# 0020. 输出命名「先分片、后版本」，整个 Group 一份元数据

- 状态：Accepted
- 日期：2026-11-02
- 来源：Issue #38（输出命名规则与多版本共享单份元数据）；父规格 #34；依据 ADR-0019

## 背景

ADR-0019 把组身份改成番号，同番号的分片与多版本（原版、`-C`、`-U`）都是同一个 Group。输出侧沿用旧规则就露了三个洞：

1. **单文件作品保留源文件名**，于是同一部作品的两种写法（`MIDA-557-C.mp4` 与后来补的 `MIDA-557.mp4`）在库里是两条；`-C` 这类版本证据留在文件名里，媒体服务器无从知道这是「中字版」。
2. **多分片时模板对每个分片生效**（`ABC-123.mp4` 也变成 `ABC-123-cd1.mp4`），与 spec §4、验收标准第 1 条（`ABC-123.mp4` 输出为 `ABC-123.mp4`）冲突。
3. 版本旗标没有落盘形状：`-U` / `无码` / `破解` / `流出` 都该是 `-破解`，`-UC` 与 `-CU` 是同一个文件。

## 决定

1. **命名规则是一条契约，不是每个部署的选择**：`{number}[-cd{part}][-中文][-破解]`。
   - 只有名字里**显式**写了分片标记才出 `-cd{n}`：`ABC-123.mp4` 与 `ABC-123-cd2.mp4` 同组时，前者仍是 `ABC-123.mp4`。
   - 版本顺序是**规则的顺序**，不是名字的书写顺序：`-UC` 与 `-CU` 都是 `-中文-破解`。
   - 源文件名不再进库，组内只有一个文件时也按规则渲染。
2. **`file_template` 默认值就是这条规则的模板形**：`{{ number }}{% if part %}-cd{{ part }}{% endif %}{{ version }}`。模板变量多三个：`version`（`""` / `-中文` / `-破解` / `-中文-破解`）、`chinese`、`uncensored`；`part` 在未标记分片时渲染为空，`{% if part %}` 因此能直接写。用户改模板仍然只能改「名字怎么拼」，改不了「版本有没有」——版本是证据，不是样式。
3. **分片证据要过 `task_files` 这一关**：`part_index` 记名字里的标记，无标记就是 `0`；「无标记算第 1 片」只留在排序（`Part.Index()`）。任务落盘与重跑都从 `task_files` 重建组，这里若存 `1`，单文件作品会莫名变成 `-cd1`。
4. **整个 Group 共享一份 `movie.nfo` 与一套封面**（`poster.jpg` / `fanart.jpg`）：同番号的全部产物是 `{root}/{number}/` 里的硬链接，元数据只写一次。
5. **字幕跟的是「分片 × 版本」**：`FollowsPart` 名的是分片，而同一分片现在有多个版本；字幕按自己名字里的版本旗标选跟随对象（`ABC-123-C.zh.srt` → `ABC-123-中文.zh.srt`），没有版本证据就跟该分片的主版本（原版）。旗标从文件名重读，不加列。
6. **同一目标名只准一个来源**：两个文件解析成同一分片同一版本时，`Apply` 写入第一个、拒绝第二个并点名两个源文件，任务 `failed`。静默覆盖是唯一事后看不见的结局。

## 替代方案

- **保留 `file_template` 只管分片、版本后缀由代码追加**：被否——模板与规则各说一半，改模板的人看不到版本会怎么落。变量化把这半句话交给模板，规则本身仍在代码里。
- **多分片组一律合成 `-cd1`**：被否——与验收标准第 1 条同一把尺子对不上：有没有分片由名字决定，不由兄弟文件数量决定。
- **重名时静默覆盖 / 组内悄悄丢一个**：被否——两条同名记录意味着名字证据不够，交人看比丢文件好。

## 后果

- 同一部作品的多次下载在库里恒为一条，`-C`/`-U`/分片各自有名字。
- 验收环境的输出期望跟着改：`MIDA-557-C.mp4` → `MIDA-557-中文.mp4`，场景名文件 `MIDV-804.2025.1080p…-MTeam.mkv` → `MIDV-804.mkv`。
- 重名会让任务 `failed` 而不是留下半对文件；改名或删一个再重跑即可（重跑从 `task_files` 起，不重扫目录）。
