# 0010. 重跑是任务级后缀 + 新 task_run，历史保留

- 状态：Accepted
- 日期：2026-10-27
- 来源：wayfinder 票「Pipeline 步骤模型」（#2）、「任务与存储模型」（#9）

## 背景

NFS 上全树 walk 是贵操作；任务重跑如果重扫目录，代价随任务数放大。同时排障需要「上次到底跑了什么」的证据，所以历史不能就地覆盖。

## 决定

- **重跑 = 任务级后缀**（`parse` 起），文件集合从 `task_files` 读，**不重扫目录**。
- 每次重跑开一行 `task_runs`（`run_no` 自增）；`step_runs`/`source_runs`/`file_rows` 都挂这次 run；**历史保留，V1 不清理**。
- 幂等基准是**输出目录**；按最近一次 run 的 `file_rows` diff 清理旧产物。
- 按**当前**同名 pipeline 跑（不做配置快照、不做配置指纹）；文件不存在 → 任务 `failed`，错误点名缺哪条流水线。
- 在跑任务重跑 → 409；待补号填号 → 任务回 `queued` 开新 run 从 `parse` 起。
- **不做「从任意步骤重跑」**。

## 替代方案

- 重跑重扫目录：被否 —— NFS 代价。
- 就地覆盖历史（旧仓部分如此）：被否 —— 排障要「上次跑了什么」。
- 从任意步骤重跑：被否 —— 需要把中间产物落库或可重放，与「大产物不落库」冲突。

## 后果

- `step_runs.summary_json` 只需摘要（计数 + 前 N 条），没有重放需求。
- 前端详情页的留痕数组只给**最近一次 run**。
- 任务与批次只增不减，删除是第二批的事（第一问：删任务算不算删输出目录）。
