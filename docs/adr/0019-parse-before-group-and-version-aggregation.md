# 0019. 解析先于分组，按番号跨目录聚合多版本与分片

- 状态：Accepted
- 日期：2026-10-31
- 替代：ADR-0002、ADR-0003
- 来源：Issue #33（重构 group 与 parse 流水线）

## 背景

原 ADR-0002 采取「先分组、后解析」策略，依赖同目录下的文件名编辑距离（Levenshtein ≤ 2）与分片标记合并视频。但在实际场景中，该方案暴露了显著痛点：
1. 异构命名（如 `hnvr00152.part1` 与 `HNVR-152.part3`，见 #33）因前导零填充差异，编辑距离超出阈值而无法合并；
2. ADR-0003 将同主干的重复版本（如原版 `ABC-123.mp4` 与中字版 `ABC-123-C.mp4`）视为 `duplicate_stem` 拒绝自动合并，转交人工判定，导致多版本库维护极其繁琐；
3. 同部影片的多版本或分片散落在不同子目录下时无法归一化整合。

## 决定

1. **流水线拓扑调整**：
   - 将批次级前缀调整为 `scan` → `filter` → `parse` → `group`；
   - 扇出点位于 `group` 之后，`scrape` 起作为任务级执行单元（每个 Group / 番号一个 Task）。
2. **parse 阶段职责**：
   - 逐文件消费 `Candidates`，统一解析并产出：
     - 标准番号（`Number`，经前导零归一化）；
     - 分片序号（`PartIndex`，如 `cd1`、`part2` 等）；
     - 版本旗标（`Flags`：`IsChinese` 由 `-C`/`_C`/`-ch`/`中文`/`中文字幕` 等识别；`IsUncensored` 由 `-U`/`_U`/`无码`/`破解`/`流出` 等识别，内置正则库并支持配置扩展）；
   - 若文件无法解析出番号（`no_candidate` / `ambiguous`），作为单文件独立 `needs_number` 待补号任务记录。
3. **group 阶段职责**：
   - 消费 `Parsed`，依据**归一化番号（Number）**跨扫描目录聚合；
   - 同番号的所有分片与不同版本（原版、-C、-UC）全部聚入同一个 Group；
   - 组内主视频（`Primary`）优选策略：Part 序号最小者（Part 1 优先），同分片多版本下按「原版 > 中文 > 破解」决出。
4. **输出与命名契约**：
   - 输出命名格式遵循「先分片、后版本」规则：
     - 单原版：`ABC-123.mp4`
     - 单分片：`ABC-123-cd1.mp4`
     - 中字版：`ABC-123-中文.mp4`
     - 破解中字版：`ABC-123-中文-破解.mp4`
     - 中字多分片：`ABC-123-cd1-中文.mp4`
   - 全组共享一份刮削元数据、`movie.nfo` 与封面海报。
5. **元数据复用机制**：
   - 针对后续批次新进来的同番号文件（例如库中已刮削 `ABC-123`，后续新下载了 `ABC-123-C.mp4`），若数据库已有成功元数据或目标输出目录已有有效 `movie.nfo`，优先复用已有元数据并跳过外部网络爬虫请求，直接生成硬链接落盘。

## 后果

- 彻底消除前导零与异构命名对分片合并的干扰（#33 自然解决）；
- 替代 ADR-0002 与 ADR-0003，多版本影片自动归入同一番号工作区；
- 需要重构 `parseStep` 与 `groupStep` 的接口与契约，更新 `StepRegistry` 及相关流水线调度测试。
