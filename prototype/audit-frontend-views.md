# 技术审计：`frontend-views.html`

**目标**：`prototype/frontend-views.html`（本仓唯一的 web UI，一次性原型，非待发布代码）
**模式**：Operate（访客要完成任务：查番号、看待补号、填号、排障）
**方式**：`impeccable detect` 渲染态扫描（桌面 1440 / 移动 390×844、768×1024、1920×1080）+ Chromium via CDP 实测 DOM
**评分**：**18 / 20 · Excellent（只剩打磨）**

> 证据限制：本环境无 vision provider，截图（`/tmp/shots2/`）生成了但**没有被看过**。所有结论来自机械证据：渲染态检测器的真实像素/计算样式对比度、CDP 实测的尺寸与可聚焦性、真实键盘事件驱动的焦点环与陷阱、以及真点击驱动的交互序列。凡未经渲染验证的项都在下文标注。

## 实现完整性裁决

**通过。** 界面不可能被误认成通用后台：番号 / 分片标记 / 待补号候选 / 源留痕六档原因码 / 落盘台账 / 容器内目录选择器（`browse_roots` 白名单 + 越界报错）都是本产品语义。颜色、间距、字阶、动效全部收敛到一处 token，三变体只引用不复制。

## 本轮修掉的两个真 bug

1. **`state=error` 只在任务列表出横幅** —— 扫描/详情/待补号静默忽略错误态。三个变体同形，已改为每视图都有对应文案的 `role=alert` 横幅 + 重试。
2. （上一轮，记录在此）空 `#lb` 是常驻全屏遮罩、吃掉所有点击；放大图键盘不可达。均已修。

## 仍未消除的一条（已证伪）

`monotonous-spacing: ~4px used 8/10 times (80%)`，每个视图都报。

证伪依据：
1. 把 `--sp-1` 分别设为 **4 / 7 / 12px**，snippet 一字不变；
2. 一个刻意「全 20px 均匀间距」的对照页反而 **clean**；
3. 本文件声明的间距分布是 8px(69) > 12px(48) > 4px(27) > 16px(19) > 20px(13)，不存在某个值占 80%。

结论：该规则对本文件的输入不敏感，属误报。**不要为了消掉它去改间距。**

## 已知缺口（如实标注，不是缺陷）

- **未上真机**：响应式结论全部来自 CDP 视口模拟；真机触摸手势、iOS 聚焦缩放、Safari 渲染未测。原型没有自定义拖拽面（无 slider / 无自绘拖拽条），所以「中断手势」类检查不适用。
- **未做真实屏幕阅读器**：可访问名称与语义角色是程序化验证的，没有 NVDA/VoiceOver 实听。
- **未做 200% 浏览器缩放实测**：只验证了等效窄视口（720px 下无溢出、表格转卡）。
- **Windows 高对比模式**未测；状态色已用「点 + 文字」双编码，不依赖颜色单通道。

## 留给实现阶段

- 原型是手写 CSS，生产走 **Tailwind v4**：搬 token 的**角色划分**（surface / text / line / accent / 7×ink-mark-tint / 间距 / 字阶 / 动效），值别搬。
- 假数据、内存态、整树 `innerHTML` 重渲染、`selectorFor`/`rerender` 焦点补丁都是原型专用，**不是**实现参照。
